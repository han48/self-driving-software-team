# Steering: Generating RADIO Report

## When to Apply
When AI needs to report progress after each task/sprint or when there is a significant change.

## Update Frequency (Mandatory)

| Trigger | When | Mandatory |
|---------|------|-----------|
| Task complete | Each time a task changes to `[x]` | ✅ |
| Test fail | When CI reports failure | ✅ |
| New blocker | When a blocker/risk is discovered | ✅ |
| End of day | End of day (if there is progress) | ✅ |
| Sprint end | Sprint summary | ✅ |
| Milestone | Completing a wave in dependency | Recommended |
| **Minimum** | **At least once/day if active** | ✅ |

## Rules

1. **File location:** `openspec/specs/{feature-name}/radio.md`

2. **radio.md file structure:**
   ```markdown
   # RADIO Report: [Feature name]

   **Date updated:** YYYY-MM-DD
   **Sprint/Phase:** [Sprint X]
   **Generated by:** AI Agent
   **Reviewed by:** [Human – if reviewed]

   ---

   ## Latest Report

   **R (Review):** [Current status, specific metrics]
   **A (Action):** [What is being done, next steps]
   **D (Difficulty):** [Blockers, risks, issues – or "None"]
   **I (Information):** [Context affecting progress – or "—"]
   **O (Outcome):** [Results achieved, numbers]

   ---

   ## History

   ### [YYYY-MM-DD]
   - R: [...]
   - A: [...]
   - D: [...]
   - I: [...]
   - O: [...]

   ### [YYYY-MM-DD]
   - R: [...]
   - A: [...]
   - D: [...]
   - I: [...]
   - O: [...]
   ```

3. **RADIO content rules:**
   - R: from test results, spec compliance %, tasks.md status (X/Y done)
   - A: from tasks.md (task currently in-progress)
   - D: from risk-issue register, test failures, dependency issues
   - I: from monitoring, external factors, stakeholder updates
   - O: from CI/CD results, coverage %, tasks completed count

4. **"D" items importance:**
   - Each serious D item → check if RISK-XXX or ISSUE-XXX already exists
   - If not → create immediately
   - Critical D items must be escalated in RADIO

5. **History:**
   - Each time AI generates new RADIO → Latest Report is updated, old report moves to History
   - History sorted newest first
   - Keep maximum 10 most recent entries (older ones may be archived)

6. **No subjectivity:** RADIO must be based on data, not feelings

7. **Required sections:**

   | Section | Mandatory |
   |---------|-----------|
   | `# RADIO Report: [Name]` | ✅ |
   | Header metadata (Date, Sprint, AI, Human) | ✅ |
   | `## Latest Report` | ✅ |
   | R, A, D, I, O (all 5 items) | ✅ |
   | `## History` | ✅ |
