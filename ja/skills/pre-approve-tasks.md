# Skill: Pre-Approve Check – Tasks

## 目的
tasks.md を Human に承認提示する前に、自動チェックリスト検証を実行する。

## 入力
チェック対象のファイル `tasks.md` + `design.md`（承認済み）。

## 自動チェックリスト

### フォーマット＆構造
- [ ] 見出しが `# Implementation Plan: [Name]` である
- [ ] セクション `## Overview` がある
- [ ] セクション `## Tasks` がありネストされたチェックボックスがある
- [ ] すべてのタスクが `- [ ] N.` または `- [ ] N.M` 形式を使用している
- [ ] `## Task Dependency Graph` があり JSON waves 形式である
- [ ] JSON waves 構文が有効（パース可能）

### 粒度＆品質
- [ ] 各サブタスクの説明が AI が実行できるほど明確（汎用的すぎない）
- [ ] 大きすぎるタスクがない（見積もりがある場合 > 4h）
- [ ] 各サブタスクが `_Requirements: X.X_` で終わっている

### デザインカバレッジ
- [ ] design.md のすべてのコンポーネントに対応するタスクがある
- [ ] すべてのデータモデルにマイグレーション/モデルタスクがある
- [ ] テスト用タスクがある（ユニット、インテグレーション、E2E）
- [ ] プロパティベーステスト用タスクがある（デザインに Correctness Properties がある場合）

### 依存関係
- [ ] タスク依存関係グラフがすべてのタスク番号をカバーしている
- [ ] 循環依存がない
- [ ] 後のウェーブのタスクが前のウェーブのタスクに正しく依存している
- [ ] 「孤立」タスクがない（どのウェーブにも含まれていない）

### トレーサビリティ
- [ ] 各サブタスクが少なくとも1つの要件番号を参照している
- [ ] すべての要件が少なくとも1つのタスクから参照されている
- [ ] プロパティテストタスクが次の形式を持つ: `**Property N: [Name]**` + `**Validates: Requirements X.X**`

## 出力フォーマット

```markdown
# Pre-Approve Check: Tasks

**File:** [path]
**チェック日:** YYYY-MM-DD
**結果:** X/Y 項目 PASS

## 要件トレーサビリティ

| 要件 | カバーするタスク | ステータス |
|------|---------------|--------|
| Req 1.1 | Task 3.1, 4.2 | ✅ |
| Req 2.3 | ❌ タスクなし | ❌ |

## 依存関係グラフ検証

- ウェーブ数: 4
- 総タスク数: 12
- 孤立タスク: 0
- 循環依存: なし ✅

## 承認前に修正すべき問題

1. **Requirement 2.3** をカバーするタスクがない
2. **Task 5** が依存関係グラフに含まれていない

## 推奨事項

- [ ] 問題を修正 → pre-approve check を再実行
- [ ] すべて PASS 後 → Human に承認を提示
```
