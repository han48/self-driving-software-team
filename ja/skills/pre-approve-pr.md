# Skill: Pre-Approve Check – Pull Request (Code)

## 目的
コード変更を Human に PR 承認提示する前に、自動チェックリスト検証を実行する。

## 入力
コード変更（diff）+ 関連する `requirements.md` + `design.md` + `tasks.md`。

## 自動チェックリスト

### 仕様準拠
- [ ] コードが仕様の受入基準に従って正しく実装されている
- [ ] 実装で漏れている要件がない
- [ ] API エンドポイントがデザインと一致している（ルート、メソッド、入出力）
- [ ] データモデルがデータベース設計と一致している（カラム、型、リレーション）

### テスト結果
- [ ] すべてのユニットテストが PASS
- [ ] すべてのインテグレーションテストが PASS
- [ ] E2E テストが PASS（該当する場合）
- [ ] テストカバレッジ ≥ 80%
- [ ] プロパティベーステストが PASS（該当する場合）

### コード品質
- [ ] ハードコードされたシークレットがない（API キー、パスワード、トークン）
- [ ] 未解決の TODO/FIXME/HACK コメントがない
- [ ] デッドコードがない（未使用のインポート、到達不能コード）
- [ ] console.log/print デバッグ文がない
- [ ] エラーハンドリング: 例外の握りつぶしがない（空の catch ブロック）
- [ ] ロギング: デバッグに十分で、機密データがログに出力されていない

### セキュリティ（基本）
- [ ] すべてのユーザー入力にバリデーションがある
- [ ] パラメータ化クエリ（SQL に文字列結合を使用していない）
- [ ] XSS 脆弱性がない（出力エンコーディング）
- [ ] 保護されたエンドポイントに認証チェックがある
- [ ] 機密データがレスポンス/ログに含まれていない

### デザイン準拠
- [ ] コードが design.md のアーキテクチャパターンに従っている
- [ ] コンポーネントの責務が正しい（God クラス/関数がない）
- [ ] 命名規則が一貫している
